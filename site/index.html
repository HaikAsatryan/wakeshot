What keeps the PC awake

Wakeshot calls each reason to stay awake a hold. While any hold runs, the PC stays awake, even with the laptop lid closed. When the last one ends, the PC sleeps as usual, as if Wakeshot were not there.

AI agents

Claude Code, Codex CLI, Copilot CLI, Copilot in VS Code and OpenCode, each one tested live. Wakeshot reads the small files each agent keeps, and a session holds while it works on your task. No edits to an agent's settings, and your prompts are never stored or logged. The exact rules for each agent are in the README.

wakeshot run

Put it before any long command: a build, a test suite, a backup. Such as wakeshot run -- npm test. The PC stays awake until the command ends, and the command keeps its exit code.

Hold files

Any script can hold the PC awake by writing a small JSON file. The hold lasts while the process named in it runs. The format.

Keep awake

From the menu: 30 minutes, 1, 2 or 4 hours, or until you turn it off, with Keep screen on if you want it. It ends at sign-out or restart, so a forgotten one never survives a reboot.

Automatic in the menu, on by default, is the switch for the agents, wakeshot run and hold files. Keep awake works either way.

For an agent not on the list, wakeshot run -- <agent> holds for as long as the agent runs.

The list grows with each version. Not supported yet: Cursor, Antigravity and VS Code's own Local chats. Each can stop without a sign that its work ended, and Wakeshot never guesses with a timer. Why, for each.

A night with Wakeshot

  1. You give your AI agent a long task and walk away. The icon's light comes on. Your screen still turns off on its usual timer; only sleep waits.
  2. You close the lid. A short chime says the laptop keeps running, and Wakeshot locks it, so a closed laptop never runs unlocked.
  3. The agent finishes in the night. Wakeshot puts your lid and sleep settings back at once. After 5 minutes with no input, a soft "going to sleep" sound plays and Wakeshot puts the laptop to sleep, where Windows would have put it when you closed the lid.
  4. Morning. You open the lid and sign in. A notice says how long the PC ran with the lid closed, and what kept it running.
  5. The battery ran low instead? Below Windows' own energy saver level, Wakeshot steps back and puts your settings back. A closed laptop then goes to sleep after 5 minutes with no input.

What you see

A small icon in the tray shows what is going on, and its tooltip names what holds the PC awake.

IconStateThe tooltip says
Holding: something needs the PC. It stays awake, and closing the lid does not stop it. Holding awake: Codex (1 session)
Idle: Automatic is on, and nothing needs the PC right now. Not holding, the PC sleeps as usual
Off: Automatic is off, so Wakeshot watches nothing. Keep awake still works. Automatic is off, the PC sleeps as usual

The menu has Automatic, Keep awake (with Keep screen on), Restore my power settings, Open log and Quit. It follows your taskbar's light or dark mode, like Windows' own tray menus. A hold that starts or ends shows only in the icon and its tooltip; anything Wakeshot does on its own gets a notice.

What it changes on your PC

When nothing holds, Wakeshot changes nothing. While something holds, it asks Windows to keep the system running, and changes three settings of your active power plan:

SettingWhile holdingWhy
Lid close, plugged inDo nothingNo power request can stop a lid close; only this setting keeps a closed laptop working
Lid close, on batteryDo nothingThe same
Sleep after, on batteryNeverOn battery, Windows ends every power request about 5 minutes after this timeout, lid open or closed

After work that ended with the lid closed, Wakeshot also sets the screen and sleep timeouts to 1 minute where yours are longer, so that Windows puts the laptop to sleep. They go back as soon as you open the lid or use the PC.

  • Your own values come back when the work ends, at Quit, at sign-out, at the next start and at uninstall. If Wakeshot crashes, a small guard process puts them back.
  • Change one of these settings yourself during a hold, and your change wins at once. Restore my power settings in the menu puts them back right away.
  • Wakeshot never lowers your security: close the lid while something holds, and it locks the PC.
  • It never needs admin rights and never touches other apps.

Every detail, and the rare cases where your settings stay changed for a while, are in the README.

Install

Not released yet. The first release is on its way; until then there is nothing to install. This is how it will go.

With winget, in a terminal:

winget install HaikAsatryan.Wakeshot

Then start Wakeshot once from the Start menu. From then on it starts by itself each time you sign in. Or download the Setup yourself:

  1. Download the Setup for your PC from Releases:
    • most PCs: HaikAsatryan.Wakeshot-win-x64-Setup.exe
    • Windows on Arm: HaikAsatryan.Wakeshot-win-arm64-Setup.exe
  2. Run it. It installs for your user only and never asks for admin rights. Wakeshot starts right away, and from then on at each sign-in.
  3. Its icon may hide under the ^ arrow on the taskbar. The first notice says how to keep it in view.

Not signed yet. v1 is not code-signed, so Windows SmartScreen may stop Setup with "Windows protected your PC". Click More info: it names the Setup file and an unknown publisher. Then click Run anyway.

Updates. Wakeshot updates itself from GitHub Releases, and only while nothing holds, so an update never cuts your work short.

Uninstall from Settings > Apps, like any app. It puts your power settings back if a hold was running.

Privacy

  • No telemetry and no account.
  • The only network calls are the update checks and downloads, to GitHub.
  • The log stays on your PC. It never holds your prompts, transcript text or full command lines.
  • Wakeshot only reads the files each agent keeps. OpenCode's database it opens read only, and never the tables with OpenCode's login.
  • This page has no scripts and no trackers, and loads nothing from other sites. GitHub Pages, which hosts it, logs each visitor's IP address for security, as GitHub's own docs say.
